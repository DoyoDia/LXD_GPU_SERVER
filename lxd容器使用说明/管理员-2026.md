# 实验室 GPU 服务器 LXD 管理员手册（2026 版）

这份手册面向管理员，目标是把“给新用户发一个可用 GPU 容器”这件事做成标准流程。

---

## 1. 管理思路

推荐把实验室容器分成三层：

1. **基础镜像**：例如 `ubuntu:24.04`
2. **母本镜像**：例如 `ubuntu-24.04-gpu-desktop`
3. **用户实例**：例如 `user-2026-01`

这样做的好处：

- 升级和回滚都容易
- 新用户开通速度快
- 环境更统一
- 出问题时更容易复现

---

## 2. 查看已有镜像与实例

### 查看镜像

```bash
lxc image list
```

### 查看实例

```bash
lxc list
```

### 查看更详细信息

```bash
lxc info <实例名>
lxc config show <实例名> --expanded
```

---

## 3. 从镜像创建新容器

### 从官方 Ubuntu 镜像直接创建

```bash
lxc launch ubuntu:24.04 user-2026-01
```

### 从本地母本创建

```bash
lxc launch local:ubuntu-24.04-gpu-desktop user-2026-01
```

如果有统一 profile，也可以同时指定：

```bash
lxc launch local:ubuntu-24.04-gpu-desktop user-2026-01 --profile default --profile lab-user
```

---

## 4. 给容器配置资源

建议优先写进 profile，而不是每台机器都单独乱改。

### 创建 profile

```bash
lxc profile create lab-user
lxc profile edit lab-user
```

示例：

```yaml
config:
  limits.cpu: "8"
  limits.memory: 16GiB
  nvidia.runtime: "true"
description: Lab user profile
devices:
  root:
    path: /
    pool: default
    size: 200GiB
    type: disk
```

应用到容器：

```bash
lxc profile add user-2026-01 lab-user
```

### 临时单独修改

```bash
lxc config set user-2026-01 limits.cpu 8
lxc config set user-2026-01 limits.memory 16GiB
```

> `limits.memory` 是上限，不是物理预留。
> 多个容器的 limit 总和可以超过宿主机 RAM，但真实同时吃满时会顶到宿主机内存墙。

## 5. 给容器分配 GPU

### 先确认宿主机驱动正常

```bash
nvidia-smi
```

### 打开 NVIDIA runtime

```bash
lxc config set user-2026-01 nvidia.runtime true
```

### 分配全部 GPU

```bash
lxc config device add user-2026-01 gpu0 gpu
```

### 分配指定 GPU

先查看资源：

```bash
lxc info --resources
```

再按 PCI 地址绑定：

```bash
lxc config device add user-2026-01 gpu0 gpu pci=0000:65:00.0
```

### 验证

```bash
lxc exec user-2026-01 -- nvidia-smi
```

---

## 6. 给容器开放 SSH / RDP 端口

如果不能桥接，建议继续使用 proxy device。

### 查看宿主机 IP

```bash
ip addr
```

### 查看容器 IP

```bash
lxc list
```

假设：

- 宿主机 IP：`192.168.1.10`
- 容器 IP：`10.0.0.123`

### 映射 SSH 端口

```bash
lxc config device add user-2026-01 ssh proxy \
  listen=tcp:192.168.1.10:22001 \
  connect=tcp:10.0.0.123:22 \
  bind=host
```

### 映射 RDP 端口

```bash
lxc config device add user-2026-01 rdp proxy \
  listen=tcp:192.168.1.10:23389 \
  connect=tcp:10.0.0.123:3389 \
  bind=host
```

### 查看实例配置

```bash
lxc config show user-2026-01
```

### 删除错误端口映射

```bash
lxc config device remove user-2026-01 ssh
lxc config device remove user-2026-01 rdp
```

## 7. 初始化容器内部环境

进入容器：

```bash
lxc exec user-2026-01 -- bash
```

推荐最低初始化：

```bash
apt update
apt install -y openssh-server curl git vim htop tmux
adduser dev
usermod -aG sudo dev
systemctl enable --now ssh
```

推荐补充：

```bash
apt install -y locales
locale-gen zh_CN.UTF-8 en_US.UTF-8
update-locale LANG=zh_CN.UTF-8
```

## 8. 桌面环境

默认路线保留 **`ubuntu-desktop` 官方体验**，XFCE 作为备选方案。

### 默认路线：Ubuntu Desktop + XRDP

```bash
apt update
apt install -y ubuntu-desktop xrdp
systemctl enable --now xrdp
echo gnome-session > /home/dev/.xsession
chown dev:dev /home/dev/.xsession
```

适合这些场景：

- 希望用户拿到的就是标准 Ubuntu 桌面
- 更看重“上手一致性”
- 用户里 Linux 新手比较多

### 备选路线：XFCE + XRDP

```bash
apt update
apt install -y xfce4 xfce4-goodies xrdp
systemctl enable --now xrdp
echo xfce4-session > /home/dev/.xsession
chown dev:dev /home/dev/.xsession
```

更适合这些场景：

- 一台宿主机上要给很多用户都开桌面
- 更在意资源占用和远程流畅度
- 不要求完全保持官方 Ubuntu 桌面外观

如果只是写代码、跑训练、看日志，统一要求走 SSH / VS Code Remote SSH 就够了。

## 9. 制作母本镜像

一台容器初始化完成后，建议立刻做模板。

### 停止容器

```bash
lxc stop user-2026-01
```

### 发布为默认桌面模板

```bash
lxc publish user-2026-01 --alias ubuntu-24.04-gpu-desktop
```

### 用模板创建新容器

```bash
lxc launch local:ubuntu-24.04-gpu-desktop user-2026-02
```

### 低资源场景可额外做一份 XFCE 模板

```bash
lxc publish user-2026-01 --alias ubuntu-24.04-gpu-xfce
```

### 删除旧模板（如果需要重做）

```bash
lxc image delete ubuntu-24.04-gpu-desktop
```

## 10. 快照与回滚

做大改动前建议先打快照。

### 创建快照

```bash
lxc snapshot user-2026-01 before-cuda-update
```

### 查看快照

```bash
lxc info user-2026-01
```

### 回滚

```bash
lxc restore user-2026-01 before-cuda-update
```

---

## 11. 删除实例

### 停止

```bash
lxc stop user-2026-01
```

### 删除

```bash
lxc rm user-2026-01
```

如果是强制删除：

```bash
lxc rm -f user-2026-01
```

---

## 12. 共享目录

推荐用普通 `disk` device：

```bash
lxc config device add user-2026-01 shared disk source=/data/shared path=/mnt/shared
```

不要默认把容器改成特权模式。

如果权限有问题，优先排查：

- 宿主机目录属主属组
- 宿主机目录权限
- 容器 UID/GID 映射

---

## 13. 容器里跑 Docker（可选）

如果真的需要：

```bash
lxc config set user-2026-01 security.nesting true
lxc restart user-2026-01
```

然后在容器内安装 Docker。

提醒：

- 不是每个用户都需要 Docker
- 嵌套 Docker + GPU 会显著增加维护成本
- 能直接在 LXD 容器里跑的工作负载，尽量不要再套一层

## 14. 建议的管理员命名规范

### 容器名

- `user-2026-01`
- `cv-lab-a01`
- `student-liu`

### profile 名

- `lab-user`
- `gpu-single`
- `gpu-heavy`

### 模板镜像名

- `ubuntu-24.04-base`
- `ubuntu-24.04-gpu`
- `ubuntu-24.04-gpu-desktop`
- `ubuntu-24.04-gpu-xfce`

统一命名比“test、demo、final2、newnew”这种名字可维护得多。

---

## 15. 推荐的开通流程

给一个新用户开通环境，推荐按下面顺序做：

1. 从母本镜像创建实例
2. 应用 profile
3. 分配 GPU
4. 映射 SSH 端口
5. 按需映射 RDP 端口
6. 初始化用户账号和密码 / SSH key
7. 验证 `nvidia-smi`
8. 给用户发送连接说明

---

## 16. 推荐留给用户的说明

建议在容器里放一个 `/home/dev/README_FIRST.txt`，至少写清楚：

- 容器名称
- SSH 连接方式
- 是否有 RDP
- 使用的是 Ubuntu Desktop 还是 XFCE
- 分配到的 GPU
- 磁盘上限 / 内存上限 / CPU 上限
- 常见目录位置
- 管理员联系方式

这样会比口头传达稳定得多.
