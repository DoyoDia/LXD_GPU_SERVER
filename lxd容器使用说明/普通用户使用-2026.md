# 实验室 GPU 服务器 LXD 普通用户使用说明（2026 版）

这份说明面向普通用户。

你不需要理解 LXD 的全部原理，只需要知道：

- 你拿到的是一台独立的 Linux 开发环境
- 它运行在实验室 GPU 服务器上
- 你可以通过 SSH、VS Code Remote SSH，或者按需通过远程桌面来使用它

---

## 1. 你会拿到什么

管理员通常会给你这些信息：

- 宿主机 IP
- SSH 端口
- 用户名
- 初始密码，或者 SSH 公钥登录方式
- 是否给你开了远程桌面
- 你被分配到的 GPU

例如：

- 宿主机 IP：`192.168.1.10`
- SSH 端口：`22001`
- 用户名：`dev`

---

## 2. 推荐使用方式

按推荐程度排序：

1. **VS Code Remote SSH**
2. **普通 SSH**
3. **远程桌面（RDP）**
4. **X11 转发**

### 为什么优先推荐 SSH / VS Code

因为它们通常：

- 更稳定
- 更省带宽
- 延迟更低
- 不容易卡死整套桌面
- 更适合写代码、跑训练、看日志

如果你只是写 Python、C++、深度学习脚本，通常不需要完整桌面。

---

## 3. 使用 SSH 连接

### Windows

可以使用：

- Windows Terminal / PowerShell 自带 `ssh`
- MobaXterm
- Xshell
- PuTTY

命令格式：

```bash
ssh -p 22001 dev@192.168.1.10
```

### macOS / Linux

直接终端输入：

```bash
ssh -p 22001 dev@192.168.1.10
```

### 第一次连接

第一次连接时通常会提示确认远程主机指纹，输入：

```bash
yes
```

然后输入密码即可。

---

## 4. 使用 VS Code Remote SSH

这是最推荐的方式。

### 步骤

1. 安装 VS Code
2. 安装扩展：**Remote - SSH**
3. 在本机 `~/.ssh/config` 中加入：

```sshconfig
Host lab-gpu
    HostName 192.168.1.10
    User dev
    Port 22001
```

4. 在 VS Code 中连接到 `lab-gpu`
5. 打开远程目录开始开发

### 优点

- 代码编辑体验非常好
- 文件同步方便
- 终端直接就是远程环境
- 调试、Git、搜索都很顺手

### 注意

- 大规模训练不要只看 VS Code 终端，建议配合 `tmux`
- 长时间任务不要直接挂在前台

---

## 5. 推荐学习 `tmux`

远程服务器上跑训练，强烈建议学会 `tmux`。

### 新建会话

```bash
tmux new -s train
```

### 退出但不停止任务

按：

```text
Ctrl+b d
```

### 恢复会话

```bash
tmux attach -t train
```

这样即使你本地断网、关机，训练也不会立刻停掉。

## 6. 查看系统资源

### 看 CPU / 内存

```bash
htop
```

### 看 GPU

```bash
nvidia-smi
```

### 实时刷新 GPU 状态

```bash
watch -n 0.5 nvidia-smi
```

你应该学会看这些信息：

- GPU 利用率
- 显存占用
- 哪个进程在用 GPU

---

## 7. 远程桌面（RDP）

如果管理员给你开了 RDP 端口，你可以像连 Windows 远程桌面一样连你的容器。

### Windows

运行：

```text
mstsc
```

然后输入：

- 地址：`192.168.1.10:23389`

### macOS / Linux

安装任意支持 RDP 的客户端即可，例如：

- Microsoft Remote Desktop
- Remmina

### 适合什么情况

- 你确实需要 Linux 图形桌面
- 你要用某些图形化 IDE / 浏览器 / 文件管理器

### 不适合什么情况

- 长时间高强度训练时一直开着桌面
- 网络质量较差的环境

如果你觉得卡，优先回到 SSH / VS Code。

---

## 8. X11 转发（可选）

这个方式适合偶尔启动单个图形程序，不适合完整桌面。

例如你只想远程弹一个简单 GUI 程序，而不是登录整个桌面环境。

今天这个模式的优先级已经低于 VS Code Remote SSH 和 RDP 了。

## 9. 基本文件操作建议

### 常用目录

- 家目录：`~`
- 项目目录：建议自己统一放在 `~/projects/`
- 数据目录：看管理员是否给你挂了共享目录

### 建议

- 自己的代码统一放到固定目录
- 大数据集不要随意复制很多份
- 不清楚磁盘限额时，先问管理员

---

## 10. Python / Conda / 训练建议

### 推荐做法

- 先确认 `nvidia-smi` 正常
- 再创建自己的 Conda / venv 环境
- 不要随便改系统级 Python
- 尽量不要用 root 乱装东西

### 不推荐做法

- 把所有包装到系统 Python 里
- 为了图省事到处 `sudo pip install`
- 看见网上教程就直接执行不理解的命令

## 13. 不要做的事

下面这些事很容易把公共服务器环境搞乱：

- 长时间占满全部 GPU 但不告知他人
- 不清楚后果时用 `sudo`
- 随便删除公共目录
- 在家目录堆积大量无用 checkpoint / dataset 副本
- 一开机就自动跑很多后台程序
- 把密码随便发给别人

如果你不确定某条命令的后果，先问管理员。

---

## 14. 训练任务的基本习惯

### 跑训练前

先看：

```bash
nvidia-smi
```

确认 GPU 是否空闲。

### 跑训练时

建议：

- 用 `tmux`
- 日志重定向到文件
- 把输出目录命名清楚

例如：

```bash
python train.py > train.log 2>&1
```

或者：

```bash
tmux new -s exp1
python train.py | tee train.log
```

### 跑完训练后

记得清理：

- 无用日志
- 失败实验生成的大文件
- 重复 checkpoint

---

## 15. 遇到问题先检查什么

### 连不上 SSH

先检查：

- IP 和端口有没有输错
- 用户名有没有输错
- 管理员有没有开 SSH 端口映射

### 看不到 GPU

先跑：

```bash
nvidia-smi
```

如果报错：

- 可能是管理员还没给你分配 GPU
- 可能是容器没启用 GPU runtime
- 可能是宿主机驱动本身有问题

### VS Code 连不上

先检查普通 SSH 是否能通。

### 桌面特别卡

优先改回 SSH / VS Code，不要死磕远程桌面。

---

## 16. 推荐你的个人工作流

对大多数人来说，最舒服的一套流程是：

1. 本地 VS Code 连接远程容器
2. 在远程终端里开 `tmux`
3. 在远程环境里跑训练
4. 用 `nvidia-smi` 看 GPU
5. 用 Git 管理代码
6. 只在确实需要 GUI 时才开 RDP

这样通常最稳。

---

## 17. 你需要记住的一句话

**把它当作一台“你自己的 Linux 工作站”来爱护，但也别忘了它实际上是公共 GPU 服务器上的共享资源。**
